# Epic: Game

## Goal

Build a two-player competitive exam game. A user can choose **Start game** from an exam action area, invite another user by email or by a new 6-digit user code, wait for the invited user to accept, start the game, and then both users answer the same exam. When both users finish or the time limit expires, the app shows the winner: the player with more correct answers. Equal scores should be treated as a draw.

The current repository snapshot contains:

- `exam-ai-api` — API with existing auth, users, exams, questions, and files.
- `exam-ai-mobile` — Expo/React Native app with an existing multiplayer tab at `exam-ai-mobile/src/app/(app)/(tabs)/multiplayer.tsx`.

The request also mentions a web/Next implementation. No Next.js web application is present in the provided file tree, so this plan cannot honestly create concrete Next.js implementation issues with real repository paths. The backend API should be designed for both mobile and web clients, and a separate web/Next phase should be added once the web app path and conventions are available.

## Overall approach

1. Add backend game/session support first, because both mobile and any future web client need the same authoritative lifecycle, access control, scoring, and timer behavior.
2. Split backend into lobby/invitation lifecycle and gameplay/scoring so each API change is reviewable.
3. Add mobile lobby/history entry points using the existing multiplayer tab.
4. Add mobile play/result screens after the backend can safely grade and finalize games.
5. Defer Next.js client work until the repository actually contains or identifies the web app.

The backend should be authoritative for permissions, scoring, and time-limit completion. Clients may show timers and optimistic UI, but should not decide the winner locally.

## Phase 1 — Backend game invitations, user codes, and lobby lifecycle

Create the core game domain in `exam-ai-api`: game model, repository, routes, controller, validation, and docs. Add a unique 6-digit user invite code to users. Support creating a game for an exam, inviting by email/code, accepting an invitation, starting an accepted game, and listing games for history/lobby views.

This phase comes first because no client can implement the game flow without persistent backend game state and invitation rules.

Depends on: existing auth, user, and exam APIs.

## Phase 2 — Backend gameplay submissions, scoring, and results

Extend the game API so participants can fetch playable exam data, submit answers, and retrieve final results. Add server-side grading and authoritative completion when both players submit or the time limit expires.

This phase depends on Phase 1’s game model/lifecycle and completes the API contract needed by mobile and future web clients.

Depends on: Phase 1.

## Phase 3 — Mobile game entry points, invitations, and lobby

Update the Expo/React Native app so users can start a game from an exam, invite another user by email/code, see game history in the multiplayer tab, accept invitations, and manage the lobby until the host starts the game.

This phase comes after the lobby API exists and before gameplay UI so the invitation flow can be tested independently.

Depends on: Phase 1.

## Phase 4 — Mobile game play, timer, waiting state, and results

Add the mobile screens for playing the exam game, submitting answers, waiting for the other player, and viewing the winner/draw result. Update multiplayer history so completed games can be reopened.

This phase depends on the full gameplay/result API and the mobile lobby navigation from earlier phases.

Depends on: Phases 2 and 3.
